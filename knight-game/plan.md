# План обучения: от квадрата к платформеру на Go + Ebitengine

> **Цель:** Пройти путь от нуля до прототипа платформера, осваивая Go и Ebitengine поэтапно.
> **Метод:** Каждый этап — отдельная исполняемая программа в своей папке.
> **Прогресс:** От одной папки к другой наращиваем слои, не ломая предыдущего понимания.

## Этап 0. Двигающийся квадрат (уже сделано)

**Что освоили:**
- Инициализация Ebitengine: интерфейс `ebiten.Game`, методы `Update`, `Draw`, `Layout`.
- Игровой цикл: разделение на логику и отрисовку — 60 вызовов в секунду.
- Обработка ввода: `ebiten.IsKeyPressed` — непрерывный опрос состояния клавиш.
- Система координат: (0,0) в левом верхнем углу, Y растёт вниз.
- Приватные поля структуры (строчные буквы) и указатель-ресивер `(g *Game)`.
- `ebitenutil.DrawRect` — отладочное рисование примитивов.
- `screen.Fill` — очистка экрана каждый кадр.

## Этап 1. Фон и слои

### 1.1. Один статичный фон
**Что делаем:**
- Загружаем PNG-картинку фона через `ebiten.NewImageFromFile`.
- Рисуем фон на весь экран перед персонажем.
- Персонаж (пока красный квадрат) перемещается по статичному экрану.

**Что осваиваем:**
- `ebiten.NewImageFromFile` — загрузка изображений с диска.
- `screen.DrawImage` — отрисовка изображения (основной метод графики).
- `ebiten.Image.DrawImage` с `nil` options — отрисовка без трансформаций.
- Порядок отрисовки: что нарисовано первым — будет "под" тем, что позже.
- Разница между логическим разрешением (Layout) и физическим (SetWindowSize).

### 1.2. Фон в несколько слоёв (параллакс-эффект)
**Что делаем:**
- Загружаем 2-3 фоновых изображения (дальние горы, ближние деревья и т.д.).
- Каждый слой двигается с разной скоростью при движении персонажа.
- Слои с бесконечным повторением (тайлинг по горизонтали).

**Что осваиваем:**
- Параллакс-скроллинг: коэффициент скорости для каждого слоя (0.2, 0.5, 1.0).
- `ebiten.DrawImageOptions` — структура с параметрами трансформации.
- `opts.GeoM.Translate(x, y)` — смещение изображения при отрисовке.
- Тайлинг: вычисление смещения по модулю ширины текстуры.
- Порядок отрисовки слоёв и персонажа.
- Прозрачность PNG (альфа-канал) — слои не перекрывают друг друга полностью.

## Этап 2. Камера и большой мир

### 2.1. Статичная камера + большой мир
**Что делаем:**
- Мир размером 2000×2000 логических пикселей.
- Персонаж может летать по всей карте (управление свободное).
- Экран показывает только кусок мира (640×360). Если персонаж уходит за край — его не видно.

**Что осваиваем:**
- Концепция "мировых координат" vs "экранных координат".
- Хранение размеров мира (`worldWidth`, `worldHeight`).
- При отрисовке: преобразование мировых координат в экранные (вычитание смещения камеры).
- Отсечение объектов за границами экрана (culling) — не рисуем то, что не видно.
- Понимание, что камера — это просто `cameraX, cameraY`, которые мы вычитаем.

### 2.2. Камера следует за игроком
**Что делаем:**
- Та же программа, но камера теперь привязана к персонажу.
- Плавное следование (lerp) вместо жёсткой привязки.
- Камера не уходит за границы мира (clamping).

**Что осваиваем:**
- Линейная интерполяция (lerp): `cameraX += (targetX - cameraX) * smoothing`.
- Константа сглаживания (обычно 0.1 — 10% расстояния за кадр).
- Границы камеры: `clamp(cameraX, 0, worldWidth - screenWidth)`.
- Понятие "мёртвой зоны" (dead zone) — персонаж может немного двигаться без смещения камеры.
- Отличие логического разрешения от размеров мира.

## Этап 3. Базовая физика

### 3.1. Гравитация и пол
**Что делаем:**
- Персонаж больше не управляется свободно по Y — на него действует гравитация.
- Внизу экрана — пол (прямоугольник на весь экран по ширине).
- Персонаж стоит на полу, не проваливается сквозь него.

**Что осваиваем:**
- Переменная `velocityY` — скорость падения (пикселей/кадр).
- Постоянное ускорение: `velocityY += gravity` каждый кадр.
- AABB-коллизия (Axis-Aligned Bounding Box) — пересечение двух прямоугольников без вращения.
- Исправление пересечения (collision resolution): если персонаж внутри пола — выталкиваем наверх, обнуляем скорость.
- Флаг `isOnGround` — персонаж на земле или в воздухе.
- Переход от "летающего" управления к "наземному".

### 3.2. Платформы (one-way)
**Что делаем:**
- Несколько платформ на разной высоте.
- Персонаж может:
  - Стоять на платформе сверху.
  - Проходить сквозь платформу снизу (как в Super Mario — запрыгнуть снизу на платформу).
  - Падать, если ушёл за край платформы.

**Что осваиваем:**
- One-way collision: коллизия срабатывает только если персонаж был НАД платформой в предыдущем кадре.
- Проверка: `wasAbove && playerBottom >= platformTop`.
- Слайсы (срезы) в Go: платформы как `[]Platform`.
- Цикл `for _, p := range platforms` для проверки коллизий со всеми платформами.
- Понятие "предыдущая позиция" для определения направления движения.
- Обработка состояния "на краю" — когда персонаж частично над платформой, а частично нет.

### 3.3. Прыжки
**Что делаем:**
- По нажатию пробела персонаж прыгает вверх.
- Прыжок возможен только с земли (или с платформы).
- Опционально: двойной прыжок (флаг `canDoubleJump`).

**Что осваиваем:**
- Импульс: при нажатии прыжка `velocityY = -jumpForce` (резко вверх).
- `ebiten.IsKeyPressed` vs обработка "нажатия" (нужно ловить момент нажатия, а не зажатия).
- `inpututil.IsKeyJustPressed` — регистрирует одиночное нажатие (из пакета `ebiten/v2/inpututil`).
- Разница между непрерывным опросом и событиями.
- Состояния персонажа: `OnGround`, `InAir`, `Jumping` (переход между ними).
- Coyote time (опционально): небольшое окно после ухода с края, когда прыжок ещё возможен.

### 3.4. Стены и горизонтальные коллизии
**Что делаем:**
- Добавляем вертикальные стены.
- Персонаж не проходит сквозь стены при движении влево/вправо.

**Что осваиваем:**
- Разделение коллизий по осям: X (горизонталь) и Y (вертикаль) разрешаются отдельно.
- Сначала двигаем по X, проверяем коллизию, выталкиваем по X.
- Затем двигаем по Y, проверяем коллизию, выталкиваем по Y.
- Почему разделение по осям важно: позволяет "скользить" вдоль стены, а не застревать в углах.
- Тайловая карта как `[][]int` (двумерный массив).
- Конвертация мировых координат в индексы тайлов: `tileX = worldX / tileSize`.
- `image.Rect` — стандартная структура Go для прямоугольников.

## Этап 4. Лестницы

### 4.1. Лестница как зона
**Что делаем:**
- Определяем зону лестницы (прямоугольник).
- Когда персонаж входит в зону И нажимает W/S:
  - Гравитация отключается.
  - Управление: W — вверх, S — вниз вдоль лестницы.
- При выходе из зоны — гравитация возвращается.
- На лестнице персонаж не может прыгать (или может — решим по ходу).

**Что осваиваем:**
- Новое состояние: `OnLadder`.
- Условное отключение гравитации: `if !onLadder { velocityY += gravity }`.
- Переключение управления: стрелки — свободное движение по зоне лестницы, а не по всему экрану.
- Привязка персонажа к центру лестницы по X при входе.
- Выход из лестницы: по достижении верха/низа зоны или по горизонтальному движению.
- Концепция "зон" (триггеров) vs "твёрдых тайлов".

### 4.2. Ступеньки (опционально)
**Что делаем:**
- Полупрограмма: ступеньки как частный случай тайлов пола на разной высоте.
- Персонаж автоматически "поднимается" на ступеньку высотой в 1 тайл при ходьбе.

**Что осваиваем:**
- Механика step-up: проверка коллизии на высоте колена персонажа.
- Автоматическое смещение по Y при встрече с низким препятствием.
- Отличие ступенек от вертикальной стены.

## Этап 5. Анимации и спрайты

### 5.1. Замена квадрата на спрайт
**Что делаем:**
- Загружаем один PNG-спрайт персонажа.
- Рисуем спрайт вместо `ebitenutil.DrawRect`.
- Настраиваем размеры, точку привязки (pivot).

**Что осваиваем:**
- `ebiten.NewImageFromFile` для спрайта.
- `opts.GeoM.Translate` с учётом размеров спрайта.
- Центрирование спрайта относительно "точки стояния" персонажа.
- Связь между логическим хитбоксом (коллизия) и визуальным спрайтом (может быть больше/меньше).
- Разделение `position` (для коллизий) и `drawPosition` (для отрисовки).

### 5.2. Спрайт-лист и смена кадров
**Что делаем:**
- Загружаем спрайт-лист (spritesheet) — несколько кадров в одном PNG (например, 4 кадра idle в ряд).
- Переключаем кадры по таймеру.
- Отображаем анимацию idle.

**Что осваиваем:**
- Структура спрайт-листа: кадры слева направо.
- `image.Rect` для вырезания суб-изображения: `sprite.SubImage(rect).(*ebiten.Image)`.
- Таймер анимации: накопление времени, смена кадра каждые N миллисекунд.
- Конфигурация анимации: `frameWidth`, `frameHeight`, `frameCount`, `frameDuration`.
- `time.Duration` и `time.Tick` (но лучше свой счётчик на основе `deltaTime`).
- Цикличность анимации: `currentFrame = (currentFrame + 1) % frameCount`.

### 5.3. Анимации по состояниям
**Что делаем:**
- Добавляем анимации: idle, run, jump, fall, climb.
- Переключение анимации в зависимости от состояния персонажа (скорость, на земле, на лестнице).

**Что осваиваем:**
- Enum для состояний анимации: `AnimState` с константами `AnimIdle`, `AnimRun`, `AnimJump`, `AnimFall`, `AnimClimb`.
- Мапа `map[AnimState]*Animation` для хранения конфигураций анимаций.
- Переключение анимации: если состояние изменилось — сбросить таймер и кадр на 0.
- Приоритет анимаций (прыжок важнее бега).
- Разделение анимационных состояний и физических состояний (isOnGround vs AnimJump).
- `ebiten.GeoM` для масштабирования (если спрайты одного размера, а отображать нужно по-разному).

### 5.4. Отражение по горизонтали (flip)
**Что делаем:**
- Персонаж поворачивается лицом в сторону движения.
- При движении влево спрайт отражается по горизонтали.

**Что осваиваем:**
- `opts.GeoM.Scale(-1, 1)` — отражение по X.
- Компенсация смещения при отрицательном масштабе: `opts.GeoM.Translate(frameWidth, 0)`.
- Хранение направления: `facingRight bool`.
- Обновление `facingRight` при нажатии A/D.
- Комбинация трансформаций: сначала Scale, потом Translate (порядок важен!).
- Понятие матрицы трансформаций — почему важен порядок операций.

## Принципы, которые мы соблюдаем

1. **Каждый этап — работающая программа.** Никаких "заготовок на будущее". Всё можно запустить и увидеть.
2. **Минимальные изменения между этапами.** Каждая следующая папка отличается от предыдущей на одну новую концепцию.
3. **Сначала работает, потом оптимизируем.** Не лезем в производительность, пока не дойдём до реальных тормозов.
4. **Комментарии ко всему.** Даже к очевидному — чтобы через неделю вернуться и сразу понять.
5. **Go-way.** Используем идиоматичный Go, стандартную библиотеку где возможно, минимум внешних зависимостей (кроме Ebitengine).
